## 7.0 逆向工程师的「可复现」信仰

用 GrokLang 做 RE 的理由（第 1 章的落地版）：

1. **同一脚本 + 同一 gltk 版本 + 同一输入** → 同一哈希与结论；  
2. Native 里沉淀 **PE / 熵 / ScriptGuard / AHPK2** 等「最后一公里」；  
3. 脚本层只写 **编排与报告**，方便 `pack` 成内部工具下发。

```text
样本文件
   │
   ├─ triage（大小/MZ/哈希/熵）
   ├─ pe.parse（节区/导入/资源/overlay）
   ├─ strings + regex IOC
   ├─ 特征码 find_bytes
   ├─ 高熵区 → 疑似加密
   ├─ 对症解密（XOR / SG / AES / AHPK2…）
   └─ JSON 报告 + 可复现命令行
```

## 7.3 Triage：先建立「身份证」

**脚本**：`ch07_01_triage.glk`

## 7.4 PE 静态：`pe` 模块

### 7.4.1 API 地图（实践）

| API | 说明 |
|-----|------|
| `pe.parse(bytes, light?)` | 完整/轻量解析；`light` 可跳过巨大资源 blob |
| `pe.summary(path)` | 按路径摘要，适合大文件 |
| `pe.imports(path)` | 导入表 |
| `pe.exports(path)` | 导出表 |
| `pe.overlay(path)` | 覆盖层偏移/大小 |

### 7.4.2 你在看什么？

```text
DOS Header (MZ)
  e_lfanew ──► PE Signature
                 File Header (Machine, NumberOfSections, ...)
                 Optional Header (EntryPoint, ImageBase, ...)
                 Section Table (.text .rdata .data .rsrc ...)
                 Data Directories → Import / Resource / ...
Overlay：文件末尾超出映像的数据（安装包/附加 payload 常在此）
```

### 7.4.3 跑起来

```powershell
.\gltk.exe run learn\examples\ch07_02_pe_parse.glk -- gltk.exe
```

你应看到：`machine=34404`（0x8664 AMD64）、多个 section、imports 里 `kernel32.dll` 等。

### 7.4.4 经验清单（PE）

1. **`.text` 熵中等**；整节极高熵 → 可能加密/压缩代码。  
2. **imports 很少 + 高熵 .text** → 壳/虚拟机保护可疑。  
3. **大量 RCDATA** → AHK/脚本/资源壳常见。  
4. **overlay_size > 0** → 看尾部是否 7z/zip/PE/配置。  
5. **light 模式**先探结构，确认需要再 `parse` 带资源。  
6. **不要执行样本**；`pe.parse` 只读字节。  
7. Go 编译的 exe 常见 `/数字` 节名（如 `/4` `/19`）——正常。  
8. `resources=0` 不代表无资源；也可能解析策略/light。  

### 7.4.5 手搓 DOS/PE 签名（不依赖 pe.parse）

```powershell
.\gltk.exe run learn\examples\ch07_11_manual_mz.glk -- learn\testdata\re\04_mz_pe_sig_stub.bin
.\gltk.exe run learn\examples\ch07_11_manual_mz.glk -- gltk.exe
```

要点：

- `u16le@0 == 0x5A4D` → MZ  
- `e_lfanew = u32le@0x3C`  
- `bytes[e_lfanew..+4] == PE\0\0`  
- `machine = u16le@e_lfanew+4`（`0x8664` AMD64，`0x14c` i386）

这是面试/现场没工具时的基本功；GrokLang 让你**写成可复现脚本**。

## 7.5 字符串与 AHK 特征

### 7.5.1 两套 API

| API | 特点 |
|-----|------|
| `str.scan(data, minLen)` | 返回 `{enc, off, text}`，偏通用/AHK 友好 |
| `strings_re.extract` / `extract_utf16` | 结构化 offset/value，可配熵 |

### 7.5.2 关键字表方法（极常用）

不要人工翻几千字符串，用**标记表**过滤：

```text
AutoHotkey, ScriptGuard, Ahk2Exe, #NoEnv, SendInput, FileInstall
password, http, token, AES, RCDATA ...
```

```powershell
.\gltk.exe run learn\examples\ch07_03_strings_scan.glk
```

fixtures `01_...` 应打出多条 marker 与 UTF16 `UTF16_MARKER_GrokLang`。

### 7.5.3 经验

1. **ASCII + UTF16LE 都要扫**（Windows 资源常 UTF16）。  
2. `minLen` 太小噪声大，太大漏短密钥——从 4～6 试起。  
3. 命中 `ScriptGuard`/`Ahk2Exe` → 走 AHK 解包线。  
4. 命中 `password=`/`http` → 进 IOC 与配置分析。  
5. 字符串加密时扫不到 → 结合熵与解密循环。

## 7.6 熵：找「不像代码」的区域

```powershell
.\gltk.exe run learn\examples\ch07_04_entropy.glk
```

| 现象 | 可能含义 |
|------|----------|
| 块熵接近 0 | 重复填充 `AA..`、零页 |
| 熵 ~4–5 | 英文/源码/混合 |
| 熵 > 7 | 压缩/加密/高质量伪随机 |

**经验**：

- 安装包：高熵 + overlay。  
- 壳：入口附近跳进高熵区。  
- 全文件熵中等但局部尖峰 → `find_high_entropy` 定位再 dump。

阈值与 block size 要试：`find_high_entropy(data, thr, blockSize)`。

## 7.7 特征码：`bin.find_bytes`

```powershell
.\gltk.exe run learn\examples\ch07_05_pattern_bin.glk
```

fixtures `05_...` 内嵌三处 `DE AD BE EF`，脚本应报 **3 hits**。

**经验**：

1. 端序：`0xDEADBEEF` 在 LE 文件里常是 `EF BE AD DE`。  
2. 多命中循环：`find` 后 `start = abs+1` 再扫。  
3. 与 IDA 特征码互补：脚本适合批量；IDA 适合交互确认。  
4. 对 **gltk.exe 头** 找 MZ 应在 offset 0。

## 7.9 反汇编 `disasm`

```powershell
.\gltk.exe run learn\examples\ch07_07_disasm.glk
.\gltk.exe run learn\examples\ch07_07_disasm.glk -- gltk.exe x64 20
```

默认内置 `90 c3 48 89 c0` → `nop; ret; mov rax,rax`。

**经验**：

- 只对 **已知入口/shellcode 片段** 反汇编，不要整文件百万行。  
- `arch`：`x64` / `x86`（以实现支持为准）。  
- 结合 PE `entry` RVA → 文件偏移（需节表换算；高级可后续封装）。

## 7.10 解密入门：XOR + 哈希

```powershell
.\gltk.exe run learn\examples\ch07_08_xor_crypto.glk
```

`09_xor55_payload.bin` = `"HiddenPayloadXOR" xor 0x55`，脚本应 `match? true`。

**经验**：

1. 单字节 XOR 用已知明文攻击（crib）：猜 `http`/`MZ`/`{` 试密钥。  
2. 解完立刻 `md5/sha256` 与预期比。  
3. 多字节 XOR/RC4/AES 用 `crypto` AES API（见 crypto 模块扩展）。  
4. **不要**在脚本里写死生产密钥到公开仓库（教学 fixtures 除外）。

## 7.16 决策树（遇到未知样本）

```text
有 MZ?
  否 → 看熵/字符串/是否归档(zip/7z)/是否脚本
  是 → pe.summary / parse
        imports 极少且高熵? → 壳方向
        有 RCDATA + AHK 串? → ScriptGuard 线
        .NET 特征? → dotnet + 可能 AHPK2
        overlay 大? → 尾部 dump 再 triage
字符串大量 http/邮箱? → IOC 提取与威胁情报
全高熵无结构? → 可能纯加密 blob，缺密钥则记哈希待研
```

## 7.17 安全与法律（写进习惯）

1. **只分析你有权分析的样本**。  
2. **隔离环境**；GrokLang 脚本默认也不应去 CreateProcess 样本。  
3. 报告脱敏（密码、内网 IP）。  
4. 教学 fixtures 可公开；真实恶意软件勿上传公共仓库。

## 7.18 常见坑

| 坑 | 对策 |
|----|------|
| 整文件 read 12MB+ 卡顿 | head/range；hash 可分段 |
| pe.parse 内存暴涨 | light 模式；先 summary |
| 字符串扫不到 | 加密/压缩；先熵再解密 |
| XOR 端序/密钥错 | 已知明文、差分 |
| map 配置 null | 字面量或后赋值（第 2 章） |
| async 嵌套 fn | 顶层函数 |
| 路径反斜杠 | `/` 或 `\\` |
| 把 stub 当完整 PE | `04_` 仅签名教学 |

## 7.23 小结

1. RE 在 GrokLang 里是 **流水线脚本**，不是 GUI 点一点。  
2. **Triage → PE → 字符串 → 熵 → 特征 → 解密 → 报告** 是默认顺序。  
3. fixtures 保证 **无毒可重复**；真样本走 `testfile/` + samples。  
4. 并行与 JSON 让你从「玩票」变成「可交付」。  
5. 解包算法优先复用 Native/samples，脚本负责 **编排与证据链**。
