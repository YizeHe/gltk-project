# 第 9 章 · 编译、打包与混淆发布

> **本章目标**：掌握从源码到交付物的完整链路——`run` / `compile` / `disasm` / `pack`，理解 **GLKB 字节码**、**混淆**、**GPK1 加密打包** 与 **glrt 运行时桩**，能独立发布可复现的小工具 exe。  
> **前置**：第 1–8 章；尤其第 1 章工具链概念、第 7–8 章你想交付的脚本。  
> **示例**：`learn/examples/ch09_01` … `ch09_05`。

---

## 9.0 交付形态对比

| 形态 | 命令 | 依赖 | 适用 |
|------|------|------|------|
| 源码直跑 | `gltk run app.glk` | 需 `gltk.exe` | 开发调试 |
| 字节码 | `gltk compile` → `run .glkb` | 需 `gltk`/`glrt` 同类 VM | 内部分发逻辑 |
| **独立 exe** | `gltk pack -o app.exe` | **无**（自带 glrt） | 给同事/现场 |

```text
app.glk
  │ compile
  ▼
app.glkb  ──── disasm 可读 ─── 可选存档
  │ pack (+obfus + AEAD)
  ▼
app.exe = [glrt PE] + [密文 GLKB] + [GPK1 trailer]
```

## 9.3 `compile`：生成 `.glkb`

```powershell
.\gltk.exe compile learn\examples\ch09_01_tool.glk -o learn\examples\_tmp_ch09_tool.glkb
.\gltk.exe run learn\examples\_tmp_ch09_tool.glkb -- bob
```

| 点 | 说明 |
|----|------|
| 扩展名 | `.glkb`，魔数 `GLKB` |
| 内容 | 常量池 + 多个 proto（函数）+ 主入口索引 |
| 用途 | 存档、diff、disasm、再 pack |

示例输出概念：`wrote ... (N bytes, P protos, C consts)`。

## 9.4 `disasm`：读懂字节码

```powershell
.\gltk.exe compile learn\examples\ch09_02_compile_disasm.glk -o learn\examples\_tmp_ch09_02.glkb
.\gltk.exe disasm learn\examples\_tmp_ch09_02.glkb
```

典型片段（Hello 类程序）：

```text
; constants
K[i] = "out" / "println" / 字符串字面量 ...
; proto main
IMPORT / STOREG / LOADG / GETK / LOADK / CALL / RET
```

### 9.4.1 为何要 disasm？

1. 确认 **字符串常量**是否意外包含密钥、内网路径；  
2. 对照混淆前后常量池是否被打乱/填充；  
3. 教学理解 GLVM 不是「黑盒魔法」。

### 9.4.2 练习

对 `ch09_02` 编译后 disasm，标出 `add` 与 `main` 两个 proto，以及 `CALL` 出现次数。

## 9.5 `pack`：打出独立 exe

### 9.5.1 CLI

```powershell
# 默认：混淆 + 加密
.\gltk.exe pack learn\examples\ch09_01_tool.glk -o learn\examples\_tmp_ch09_tool.exe

# 不混淆（仍加密）
.\gltk.exe pack learn\examples\ch09_01_tool.glk -o learn\examples\_tmp_ch09_tool_plain.exe --no-obfus

# 保留中间 glkb
.\gltk.exe pack learn\examples\ch09_01_tool.glk -o learn\examples\_tmp_ch09_tool.exe --keep-glkb learn\examples\_tmp_ch09_tool.obfus.glkb
```

运行：

```powershell
.\learn\examples\_tmp_ch09_tool.exe
.\learn\examples\_tmp_ch09_tool.exe alice
```

### 9.5.2 输出字段含义

```text
input=glk obfuscated=true
glkb=... cipher=... exe=... protos=... consts=... time=...
```

| 字段 | 含义 |
|------|------|
| `glkb` | 嵌入前字节码大小（混淆后通常变大） |
| `cipher` | AEAD 密文大小 |
| `exe` | 最终 PE（**主要体积来自 glrt 桩**） |
| `consts` | 常量数（混淆会灌垃圾常量） |

### 9.5.3 脚本内 pack API

```glk
import pack
let r = pack.pack(inPath, outPath, {no_obfus: false})
// r.ok, r.obfuscated, r.glkb_size, r.exe_size, ...
```

```powershell
.\gltk.exe run learn\examples\ch09_03_pack_via_api.glk
.\gltk.exe run samples\pack_tool.glk -- learn\examples\ch09_01_tool.glk learn\examples\_tmp_ch09_from_sample.exe
```

## 9.6 默认混淆做什么？

未加 `--no-obfus` 时（见 `docs/PACK.md`）：

1. **剥源码名/行号表**，proto 改名  
2. **常量池填充**垃圾字符串  
3. **常量池打乱**并重映射引用  
4. 插入 **NOP** 雪橇  
5. 插入 **不可达垃圾块**（JMP 跳过）  
6. 整体 **ChaCha20-Poly1305** 加密；密钥与桩 PE 绑定包装  

### 对比实验

```powershell
.\gltk.exe run learn\examples\ch09_04_obfus_compare.glk
```

观察：`glkb_size` / `consts` 在混淆后显著增大；`exe_size` 两者接近（桩主导）。

### 安全预期（务必读）

| 能挡 | 不能挡 |
|------|--------|
| 随手 strings / 直接抠 .glkb | 读过 glrt 源码的定向逆向 |
| 轻度静态抄常量 | 动态调试 dump 解密后内存 |
| 提高脚本抄袭成本 | 当 DRM 保护核心密钥 |

**密钥、Token 不要只靠 pack 保密**；敏感逻辑放服务端或用户配置。

## 9.7 磁盘格式：GPK1（概念）

```text
偏移 0
  [ glrt.exe 的 PE 映像 .................. ]
  [ 密文 payload = AEAD(GLKB) ............ ]
末尾 88 字节 trailer：
  magic GPK1 | ver | flags | payload_off | payload_len
  | nonce | tag | key_blob | reserved
```

运行时：`glrt` 读自身 → 解析 trailer → 解出 GLKB → `InstallGlobals` → `VM.Run`。

**分析他人 pack 产物**时：先当普通 PE 看导入表；再找尾魔数；再谈解密——这是对抗笔记，不是鼓励盗用。

核心十条：

## 9.9 工作目录与 GUI 打包

- 控制台工具：用户从哪运行，相对路径就相对哪。  
- GUI / `windowsgui`：工作目录常是「快捷方式起始位置」，**资源请用绝对路径或相对 exe 定位**（见 `cmd/gltk-proxy-gui`）。  
- 曾出现：旧 `glrt` 缺 `clash` 模块 → 运行时报 `unknown module` → **重编 glrt 再 pack**。

## 9.12 常见错误

| 症状 | 原因 | 处理 |
|------|------|------|
| pack 找不到 glrt | 未 build stub | `go build -o glrt.exe ./cmd/glrt` |
| unknown module "xxx" | glrt 过旧 | 重编 glrt 再 pack |
| exe 双击无输出 | GUI 子系统/无控制台 | 用 cmd 启动或看是否 GUI 程序 |
| 相对路径失败 | cwd 不对 | 绝对路径或固定 chdir |
| 体积 ~12MB | 正常 | 桩内嵌完整 native |
| 要「免混淆」 | 调试 | `--no-obfus` |

## 9.16 小结

1. **开发 `run`，交付 `pack`。**  
2. **compile/disasm** 用于审计常量与教学。  
3. **混淆 + AEAD** 提高静态抄作业成本，不是绝对安全。  
4. **glrt 与 native 同步**是打包成功的第一前提。  
5. 用检查单保证「干净目录可复现」。
