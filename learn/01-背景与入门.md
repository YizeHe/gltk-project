# 第 1 章 · 背景、工具链与 Hello World

> 本章几乎不涉及复杂语法，重点是：**这门语言从哪来、用来干什么、你每天会碰到哪些程序、如何跑出第一行输出。**  
> 读完本章，你应能独立运行一个 `Hello World`，并理解「源码 / 解释运行 / 字节码 / 打包 exe」分别是什么。

---

## 1.1 为什么要有一门「逆向专用」语言？

### 1.1.1 逆向工程师的日常痛点

做样本分析、协议还原、壳与加壳脚本解密时，常见工作流是：

1. 用 IDA / Ghidra / x64dbg 等看结构；  
2. 用 Python、PowerShell 或临时 C 写脚本：读文件、扫特征、试密钥、解压资源；  
3. 脚本依赖一堆库（`pycryptodome`、`pefile`、本机 Python 版本……）；  
4. 同事复现时：**环境不一致就跑不起来**，或「我机器上能解、你机器上报错」。

问题往往不在算法本身，而在 **「分析逻辑」与「运行环境」绑得太死**：

| 痛点 | 表现 |
|------|------|
| 可复现性差 | Python 版本、依赖、路径、编码各不相同 |
| 最后一公里靠脚本 | 核心结论写在 notebook 里，无法一键交付 |
| 语言与 RE 域脱节 | 通用语言没有「开箱即用」的 PE / .NET IL / 壳格式原语 |
| 交付形态弱 | 给甲方一个 `.py` + `requirements.txt`，落地成本高 |

于是需要一种语言：**写起来像脚本一样快，但执行路径固定、能力内建、结果可复现，并且能打包成单文件工具。**

### 1.1.2 GrokLang 的创造背景

**GrokLang**（源文件 `.glk`）正是在这种背景下设计的。它的第一性目标不是「再做一个 Python」，而是：

> **服务逆向工程：把「可复现的专用逆向逻辑」写成语言级程序，而不是一次性的胶水脚本。**

具体意图包括：

1. **专用原语靠近 RE 场景**  
   通过工具包内的 **Native 模块**（Go 实现、挂到虚拟机上），直接提供例如：  
   - PE / ELF 解析  
   - 二进制读写、熵、字符串扫描  
   - 常见加密与壳相关流程（如 AHPK2、ScriptGuard 等能力的语言侧封装）  
   - 后续扩展到网络、GUI 等  

   分析师用领域词汇写流程，而不是先搭三层 Python 封装。

2. **可复现的执行模型**  
   源码先变成固定格式的字节码（`.glkb`），再由 **寄存器虚拟机 GLVM** 执行。  
   同一份字节码 + 同一版本运行时 → 行为一致，不依赖「本机是否装了某 pip 包」。

3. **「专用」可以演化成「通用」**  
   一开始能力集围绕逆向；但语言本身是图灵完备的：变量、函数、控制流、数组/映射、模块 import……  
   因此它可以逐步成为 **「专长于逆向的通用编程语言」**——日常脚本、小工具、带 GUI 的客户端，都可以用同一套语法写。

一句话概括创造背景：

```text
逆向需要「可复现的专用代码」
        ↓
设计一门带 RE 原语的语言 + 固定 VM 执行路径
        ↓
脚本生产力 + 工程可交付性 兼顾
```

## 1.2 发展脉络：从专用逆向语言到通用工具语言

语言与工具包并不是一次定型的，大致可以按能力扩张理解（概念阶段，不必记版本号）：

```text
阶段 A · 专用逆向内核
  · 词法 / 语法 / 编译器 / GLVM
  · 文件系统、二进制、基础 crypto
  · PE 等格式解析
        ↓
阶段 B · 样本与壳工作流
  · .NET / IL 辅助、AHPK2、ScriptGuard 等
  · 批量解包、报告式脚本
  · 「纯 GLTK、尽量不靠 Python 收尾」的路线
        ↓
阶段 C · 通用化
  · 更完整的语言特性（break/continue、switch、try、lambda、插值……）
  · 网络（HTTP / TCP / WebSocket）
  · GUI、打包混淆、异步等
  · 仍把「逆向与安全分析」作为主场，但语法已是通用语言
```

对学习者的意义：

- 你学的是一门 **完整编程语言**，不是宏或配置 DSL；  
- 同时，官方能力库的「重力中心」在 **二进制与分析**；  
- 用它写 Hello World、写解包器、写 SOCKS 客户端，走的是 **同一条工具链**。

工具包整体名称是 **GrokLangToolKit（gltk）**，CLI 一般是 `gltk` / `gltk.exe`。

## 1.3 你会碰到的「基础程序」

做 GrokLang 开发时，磁盘上常出现这些角色。先建立心智模型，后面章节会深入。

### 1.3.1 总览图

```text
  你写的源码          hello.glk
       │
       │  gltk run          （编译 + 立刻在 VM 里跑）
       │  gltk compile      （只编译成字节码）
       ▼
  字节码文件          hello.glkb
       │
       │  gltk run hello.glkb
       │  或  gltk pack → 独立 exe
       ▼
  执行引擎            GLVM（寄存器机）
       │
       ├── 内建/自由函数   range, len, typeof, 打开文件……
       └── Native 模块     pe, fs, crypto, out, clash, gui……
```

### 1.3.2 `gltk` —— 语言工具包命令行（你最常用）

| 子命令（概念） | 作用 |
|----------------|------|
| `gltk run <file.glk\|.glkb>` | 运行源码或字节码 |
| `gltk compile <file.glk> -o out.glkb` | 编译为字节码 |
| `gltk disasm <file.glkb>` | 反汇编字节码，便于理解/调试 |
| `gltk pack <file> -o out.exe` | 打包成独立 Windows 可执行文件（默认可带混淆） |
| `gltk version` / `repl` 等 | 版本、交互等 |

**日常开发**：改 `.glk` → `gltk run` 看结果，循环最快。

### 1.3.3 解释器？还是虚拟机？

严格说，GrokLang **主路径不是「边走 AST 边解释」**，而是：

1. **前端**：词法分析 → 语法分析 → AST  
2. **中端**：编译器生成 **寄存器字节码**（Chunk / `.glkb`）  
3. **后端**：**GLVM** 按指令分发执行  

所以：

- 口语上大家会说「用解释器跑脚本」——指 `gltk run` 一键跑起来；  
- 实现上更准确的说法是：**编译到字节码 + 虚拟机解释执行**；  
- 设计选择的好处：指令集稳定、易反汇编排查、易做打包与混淆、行为可预期。

```text
「解释器」口语  ≈  gltk run 给你的体验
「虚拟机」实现  =  GLVM 执行 .glkb
```

### 1.3.4 编译器（compiler）

把 `.glk` 变成 `.glkb` 的组件。你可以：

- **隐式使用**：`gltk run foo.glk` 内部先编译再跑；  
- **显式使用**：`gltk compile foo.glk -o foo.glkb`，把产物交给别人用同一版本 VM 运行。

### 1.3.5 打包器（packer）与运行时桩（glrt）

当你希望交付 **双击即用的 `.exe`**（例如内部小工具、解包器、代理客户端）：

```text
gltk pack app.glk -o app.exe
```

典型流水线（概念）：

1. 编译得到字节码；  
2. （默认）做一层字节码混淆；  
3. 加密嵌入；  
4. 与运行时桩 **glrt** 合成一个 PE。

| 名称 | 角色 |
|------|------|
| **packer** | 负责混淆/加密/拼接格式（如文档中的 GPK1 尾部等） |
| **glrt** | 精简运行时：解密载荷 → 装 Native → 启动 GLVM |

因此：

- 开发期：`gltk run` 最快；  
- 交付期：`gltk pack` 出单文件；  
- 分析别人打包的 gltk 程序时，会碰到「桩 + 密文载荷」形态——这本身也是逆向话题，后续章节再谈。

### 1.3.6 Native 模块

GrokLang 源码里写 `import pe, out` 时，导入的是 **VM 注册好的原生能力**（底层多为 Go 实现），不是再去启动另一个语言的解释器。

这对逆向场景很重要：**最后一公里的算法与格式解析可以沉在 Native 里，脚本层只编排流程**，既快又一致。

## 1.6 Hello World

### 1.6.1 最小可运行程序长什么样？

一份「能跑起来」的 GrokLang 程序通常具备：

1. 可选：`import` 需要的模块（打印用 `out`）；  
2. 必须：入口函数 **`main`**；  
3. 习惯：`fn main(args) { ... }`，`args` 是命令行参数列表；  
4. 用 `return 0` 表示成功退出码（约定俗成，便于脚本化）。

### 1.6.2 教程示例：打印 Hello World

请新建文件（可与教程放一起）：

**路径建议：** `learn/examples/ch01_hello.glk`

```glk
// learn/examples/ch01_hello.glk
// 第 1 章：Hello World —— 你的第一个 GrokLang 程序

import out

// 程序入口。args 是字符串数组，例如：
//   gltk run ch01_hello.glk -- foo bar
// 则 args 里会有 "foo", "bar"（具体以当前 CLI 传参约定为准）
fn main(args) {
  out.println("Hello, World!")
  out.println("Hello from GrokLang!")
  return 0
}
```

### 1.6.3 运行

在仓库根目录：

```powershell
cd D:\grokbuild\groklang\gltk
.\gltk.exe run learn\examples\ch01_hello.glk
```

**期望输出：**

```text
Hello, World!
Hello from GrokLang!
```

若路径或工作目录不对，把 `learn\examples\ch01_hello.glk` 换成你的绝对路径即可。

### 1.6.4 代码在干什么？（逐行直觉）

| 片段 | 含义 |
|------|------|
| `// ...` | 行注释，不参与执行 |
| `import out` | 导入 **输出** 相关 Native 模块 |
| `fn main(args) { ... }` | 定义入口函数 |
| `out.println(...)` | 打印一行到标准输出（并换行） |
| `return 0` | 结束 `main`，进程退出码 0 |

你还不需要理解字节码；只要记住：

```text
gltk run 你的.glk  →  （内部编译）→  GLVM 执行  →  看到打印
```

### 1.6.5 可选：先编译再运行

```powershell
.\gltk.exe compile learn\examples\ch01_hello.glk -o learn\examples\ch01_hello.glkb
.\gltk.exe run learn\examples\ch01_hello.glkb
```

效果应与直接 `run .glk` 相同。  
`.glkb` 更适合「固定版本交付脚本逻辑、只分发字节码」的场景。

### 1.6.6 可选：看一眼字节码（不必深究）

```powershell
.\gltk.exe disasm learn\examples\ch01_hello.glkb
```

你会看到类似函数原型、常量池、指令列表——那是 **VM 真正执行的东西**。  
第 1 章只需建立印象：**源码不是被 Python 执行的，而是变成了 GLVM 指令。**

### 1.6.7 和官方 sample 的关系

仓库里还有更「演示向」的示例，例如：

```powershell
.\gltk.exe run samples\hello.glk
```

`samples/hello.glk` 会多演示变量、`if`、`while`、`for` 等（第 2～3 章才系统讲）。  
**本章只需掌握 `ch01_hello.glk` 那种最小形态。**

## 1.7 心智模型小结（请记住这四句话）

1. **GrokLang 为可复现的逆向与分析工作流而生**，并成长为擅长该领域的通用语言。  
2. **`.glk` 是源码，`.glkb` 是字节码，GLVM 是执行引擎。**  
3. **`gltk` 是瑞士军刀**（run / compile / disasm / pack）；**`glrt` + packer** 负责独立 exe 交付。  
4. **第一门作业**：写出并运行 `Hello, World!`，确认工具链通畅。

## 1.8 练习

1. **改输出**  
   把 `Hello, World!` 改成带上你的名字，再 `gltk run` 一次。

2. **多打两行**  
   再调用两次 `out.println`，打印：  
   - 今天的日期（可以先手写字符串，不必调时间库）  
   - 一句话说明你为什么学这门语言  

3. **编译产物**  
   对你的文件执行 `compile`，再用 `run` 跑 `.glkb`，确认输出一致。

4. **（思考题，不用写代码）**  
   若同事没有安装 Go，只有你 pack 出来的 `exe`，他能否运行你的逻辑？  
   若他只有 `.glk` 没有 `gltk`，能否运行？  
   （提示：回顾 1.3.2 与 1.3.5。）
