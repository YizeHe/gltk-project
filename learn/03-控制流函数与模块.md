## 3.1 程序的骨架

GrokLang 可执行程序的典型形状：

```glk
import out            // 可选，按需

fn helper(x) {        // 可选：顶层辅助函数
  return x + 1
}

fn main(args) {       // 必需：入口
  // 语句序列
  return 0
}
```

**块（block）**：`{ ... }` 包住一组语句，出现在：

- 函数体  
- `if` / `else` / `while` / `for` / `switch` 的分支  
- `try` / `catch`  

块内可以再嵌套块。第 2 章的表达式，在本章里几乎都出现在语句的「条件」或「右值」位置。

## 3.2 条件：`if` / `else if` / `else`

### 3.2.1 语法

```glk
if 条件 {
  // 条件为真时执行
}

if 条件 {
  ...
} else {
  ...
}

if 条件1 {
  ...
} else if 条件2 {
  ...
} else {
  ...
}
```

- **条件**使用第 2 章的**真值规则**（`null` / `false` / `0` / `""` / 空容器为假）。  
- `else if` 可写多级。  
- 大括号 **必须有**（不像 C 的单语句 if 可省略括号——GrokLang 一律用块）。

### 3.2.2 示例：分数等级

```glk
fn grade_of(score) {
  if score >= 90 {
    return "A"
  } else if score >= 80 {
    return "B"
  } else if score >= 60 {
    return "C"
  } else {
    return "D"
  }
}
```

完整可运行：

```powershell
.\gltk.exe run learn\examples\ch03_01_if.glk
```

### 3.2.3 与三元运算符的分工

| 场景 | 推荐 |
|------|------|
| 多语句、多分支 | `if` |
| 单个表达式二选一 | `cond ? a : b` |
| 需要提前 `return` | `if` 函数内 |

```glk
let tag = x == 2 ? "is-two" : "not-two"   // 表达式
if x == 2 {                                // 语句
  out.println("two")
  do_more()
}
```

### 3.2.4 嵌套 if

```glk
if a > b {
  if a - b > 1 {
    out.println("a much greater")
  }
}
```

嵌套过深时，优先拆成函数（见 3.7），提高可读性。

## 3.3 `while` 与 `break` / `continue`

### 3.3.1 语法

```glk
while 条件 {
  // 循环体
}
```

先判断条件，为真则执行体，然后再次判断——与 C/Java/JS 相同。

### 3.3.2 `break`

立即**跳出**最内层循环。

```glk
while true {
  k = k + 1
  if k >= 4 {
    break
  }
}
```

### 3.3.3 `continue`

跳过本轮循环体**剩余语句**，进入下一次条件判断。

```glk
while n < 6 {
  n = n + 1
  if n % 2 == 0 {
    continue
  }
  sum = sum + n
}
```

### 3.3.4 经典模式

**1）计数器**

```glk
let i = 0
while i < n {
  // ...
  i = i + 1
}
```

**2）哨兵值（sentinel）**

```glk
while idx < len(buf) {
  let v = buf[idx]
  idx = idx + 1
  if v == 0 {
    break
  }
  // 处理 v
}
```

**3）「永远循环 + 内部 break」**  
适合读流、读包，直到协议说结束。

### 3.3.5 可运行示例

```powershell
.\gltk.exe run learn\examples\ch03_02_while.glk
```

## 3.4 `for-in`：遍历数组、map、`range`

### 3.4.1 语法

```glk
for 变量 in 表达式 {
  // 使用 变量
}
```

| `表达式` 类型 | 循环变量含义 |
|---------------|--------------|
| 数组 | 每个**元素** |
| map | 每个**键**（不是键值对对象） |
| `range(...)` 生成的数组 | 每个整数 |

### 3.4.2 遍历数组

```glk
for v in [10, 20, 30] {
  out.println(v)
}
```

### 3.4.3 需要下标时

语言没有 `for i=0; i<n; i++` 的 C 式三元 for，用 `range` + 下标：

```glk
let arr = ["a", "b", "c"]
for i in range(0, len(arr)) {
  out.println(i, "->", arr[i])
}
```

### 3.4.4 `range`

```glk
range(5)          // 0,1,2,3,4
range(1, 4)       // 1,2,3
range(0, 10, 2)   // 0,2,4,6,8
```

### 3.4.5 遍历 map 的键

```glk
let m = {name: "demo", port: 8080}
for k in m {
  out.println(k, m[k])
}
```

**注意**：

- 迭代的是**键**；取值写 `m[k]` 或（键为标识符时）无法用动态点号；  
- **键的顺序不保证**；不要依赖「先 name 后 port」。

### 3.4.6 `for` 中的 `break` / `continue`

与 `while` 相同，作用于最内层 `for`。

```glk
for n in range(1, 10) {
  if n == 3 { continue }
  if n == 7 { break }
  s = s + n
}
```

### 3.4.7 嵌套循环

```glk
for x in [1, 2] {
  for y in ["x", "y"] {
    out.println(x, y)
  }
}
```

### 3.4.8 可运行示例

```powershell
.\gltk.exe run learn\examples\ch03_03_for.glk
```

### 3.4.9 数组「追加」怎么办？

标准库层面若没有 `push`，常见策略：

1. 只**遍历处理**，不建新表（扫描、统计）；  
2. 已知上界时用固定数组；  
3. 用 map 当集合：`seen[key] = true`；  
4. 字符串场景用 `+` 拼接。

综合算法示例见 `ch03_09_algorithms.glk`。

## 3.5 `switch` / `case` / `default`

### 3.5.1 语法

```glk
switch 表达式 {
  case 值1:
    // ...
  case 值2, 值3:
    // 多值匹配
  default:
    // 可选
}
```

### 3.5.2 语义要点

| 点 | 说明 |
|----|------|
| 匹配方式 | 与 `==` 相同 |
| fall-through | **无**。不会像 C 那样 case 穿透 |
| 多值 | 写在同一 `case`：`case 301, 302:` |
| default | 可选；都不匹配时走 default |
| 类型 | 数字、字符串等皆可，只要 `==` 有意义 |

### 3.5.3 HTTP 风格示例

见 `learn/examples/ch03_04_switch.glk`：

```powershell
.\gltk.exe run learn\examples\ch03_04_switch.glk
```

### 3.5.4 与 if 链的选择

- 多常量分发 → `switch` 更清晰；  
- 区间（`score >= 90`）→ `if`；  
- 复杂布尔 → `if`。

## 3.6 错误处理：`try` / `catch` / `throw`

### 3.6.1 语法

```glk
try {
  // 可能失败
  throw "reason"
} catch e {
  // e 通常是错误字符串
  out.println(e)
}
```

### 3.6.2 `throw`

```glk
throw "bad input"
throw "need positive, got " + ("" + n)
```

抛出后，控制权转到**最近的** `catch`。若无 catch，VM 报错退出。

### 3.6.3 在函数边界使用

```glk
fn must_positive(n) {
  if n <= 0 {
    throw "need positive, got " + ("" + n)
  }
  return n
}

try {
  must_positive(-1)
} catch e {
  out.println(e)
}
```

### 3.6.4 封装安全操作

```glk
fn safe_div(a, b) {
  try {
    if b == 0 {
      throw "division by zero"
    }
    return a / b
  } catch e {
    out.println("safe_div catch:", e)
    return 0
  }
}
```

### 3.6.5 能力边界（重要）

文档约定（v1）：

- `throw` 与部分 **调用路径**上的错误可被 `try` 接住；  
- **并非**所有运行时失败都进 catch（例如某些底层 abort）；  
- 不要假设「一切异常都像 Java」。

### 3.6.6 可运行示例

```powershell
.\gltk.exe run learn\examples\ch03_05_try.glk
```

## 3.7 函数：`fn` 定义与调用

### 3.7.1 顶层函数

```glk
fn add(a, b) {
  return a + b
}

fn main(args) {
  out.println(add(2, 3))
  return 0
}
```

- 名字：`add`  
- 参数列表：`a, b`（无类型标注）  
- 函数体：块  
- `return 表达式` 返回值；`return` 或不写则调用方得到 `null`

### 3.7.2 参数

- 按**位置**传入；  
- 个数应匹配（过少/过多的严格程度以实现为准，编写时保持一致）；  
- 参数是函数局部绑定。

### 3.7.3 `return` 的控制流

```glk
fn max2(a, b) {
  if a >= b {
    return a
  }
  return b
}
```

`return` 立刻结束**当前函数**（不是整个程序）。`main` 里 `return 0` 结束进程逻辑。

### 3.7.4 递归

```glk
fn fact(n) {
  if n <= 1 {
    return 1
  }
  return n * fact(n - 1)
}
```

注意栈深度：极大 `n` 可能撑爆调用栈；生产可用循环改写。

### 3.7.5 多返回值

语言没有元组。用 **map** 或 **数组** 打包：

```glk
fn divmod(a, b) {
  return {q: a / b, r: a % b}
}
let dm = divmod(17, 5)
out.println(dm.q, dm.r)
```

### 3.7.6 函数是一等值

```glk
let op = add
out.println(op(10, 1))
```

可以把函数存进变量、放进 map（注意 map 字面量规则）、当作参数思路传递（配合 lambda 更常见）。

### 3.7.7 嵌套**命名**函数的限制

在 `main` 或其它函数体内部写：

```glk
fn local_helper(x) {   // 可能解析失败！
  return x
}
```

当前语法对「函数体内再 `fn 名字`」支持不完整。  
**请用 lambda**：

```glk
let local_helper = fn(x) {
  return x
}
```

## 3.8 匿名函数与闭包

### 3.8.1 Lambda 语法

```glk
let double = fn(x) {
  return x * 2
}
out.println(double(21))
```

### 3.8.2 工厂函数

```glk
fn make_adder(base) {
  let f = fn(x) {
    return x + base
  }
  return f
}
let add10 = make_adder(10)
out.println(add10(5))  // 15
```

### 3.8.3 捕获规则：按值拷贝（必读）

闭包捕获外层局部变量时，是 **创建闭包那一刻的值拷贝**，不是引用：

```glk
let n = 1
let show = fn() { return n }
out.println(show())  // 1
n = 99
out.println(show())  // 仍是 1
```

因此：

- 不要指望闭包共享可变计数器（除非你用 map 等引用对象自己封装状态）；  
- `make_adder(10)` 与 `make_adder(100)` 互不干扰。

### 3.8.4 立即调用

```glk
let v = fn(x) { return x + 1 }(41)  // 42
```

### 3.8.5 高阶用法

```glk
fn map_ints(arr, f) {
  for v in arr {
    out.println(v, "->", f(v))
  }
}
map_ints([1, 2, 3], fn(x) { return x * x })
```

### 3.8.6 可运行示例

```powershell
.\gltk.exe run learn\examples\ch03_07_lambda.glk
```

## 3.9 模块：`import`

### 3.9.1 两类导入

| 形式 | 含义 |
|------|------|
| `import out, json, pe` | **Native 模块**（VM 内建，Go 实现） |
| `import "path/to/lib.glk" as alias` | **用户库**（编译期合并进同一 Chunk） |

```glk
import out
import json
import "learn/examples/ch03_lib_math.glk" as m
import "libs/helpers.glk" as helpers
```

### 3.9.2 Native 模块

- 运行时以 **map** 形式出现：`json.parse`、`out.println`；  
- 模块在全局表注册；  
- **名字冲突**：`import str` 或全局模块表中的 `str` 会占住名字 `str`，导致 `str(42)` 变成「调用 map」。

常用组合示例：

```glk
import out, fs, json, pe, crypto
```

### 3.9.3 用户库 `.glk`

库文件特点：

- **不需要** `main`；  
- 顶层 `fn` 被导出到别名 map；  
- 可再 `import` 其它库或 native；  
- **禁止循环依赖**。

库示例 `learn/examples/ch03_lib_math.glk`：

```glk
fn clamp(x, lo, hi) { ... }
fn abs(x) { ... }
fn sum_arr(arr) { ... }
```

主程序：

```glk
import "learn/examples/ch03_lib_math.glk" as m
out.println(m.clamp(15, 0, 10))
```

### 3.9.4 路径与搜索

路径 import 会相对入口、当前目录、`libs/`、`stdlib/`、`GLTK_LIB` 等查找（详见 `docs/language.md`）。  
教程里用相对于**仓库根**的路径：`learn/examples/...`，请在仓库根执行 `gltk run`。

### 3.9.5 别名

```glk
import "libs/helpers.glk" as helpers
import "libs/helpers.glk"           // 默认别名 helpers（文件名 stem）
```

### 3.9.6 可运行示例

```powershell
.\gltk.exe run learn\examples\ch03_08_import.glk
```

## 3.11 设计建议（写可维护脚本）

1. **一个函数一件事**：`parse` / `scan` / `report` 分开。  
2. **错误用 throw + 边界 try**，或返回 `{ok, error, value}` map。  
3. **魔法数变名字**：`let MZ = 0x5A4D`。  
4. **循环里少做重复 I/O**：先读内存再扫。  
5. **库下沉通用逻辑**：`clamp`、`sum` 放 `.glk` 库。  
6. **入口 main 只做参数与编排**。

## 3.12 常见错误

| 症状 | 原因 | 处理 |
|------|------|------|
| parse expected ... `fn name` 在 main 内 | 嵌套命名函数不支持 | 改 `let f = fn(...){...}` |
| for map 得到的是键 | 设计如此 | 用 `m[k]` 取值 |
| switch 落入多个 case | 以为有 fall-through | 无贯穿；用 `case a, b:` |
| 闭包读到旧值 | 按值捕获 | 需要共享状态用 map 对象 |
| import 找不到库 | 工作目录/路径不对 | 在仓库根运行；检查路径 |
| `str(1)` 失败 | 模块名覆盖 | `to_str` / `""+` |
| break 跳出多层？ | 只作用最内层 | 用标志变量或封装函数 return |
| while 忘改计数器 | 死循环 | 每次循环推进状态 |

## 3.15 速查卡

```glk
// 条件
if c { ... } else if c2 { ... } else { ... }

// 循环
while c { ... break ... continue ... }
for x in arr { ... }
for k in map { ... m[k] ... }
for i in range(0, n) { ... }

// 分支表
switch x {
  case 1: ...
  case 2, 3: ...
  default: ...
}

// 错误
try { throw "e" } catch e { ... }

// 函数
fn add(a, b) { return a + b }
let f = fn(x) { return x + 1 }
// 捕获按值

// 模块
import out, json
import "path/lib.glk" as lib
lib.fn(...)
```

---

## 3.16 小结

1. **if / while / for / switch / try** 构成控制骨架。  
2. **for-in** 数组得元素、map 得键；索引遍历用 `range`。  
3. **switch 无 fall-through**，多值写在同一 case。  
4. **函数**是抽象与复用的核心；**lambda** 做闭包与高阶。  
5. **闭包按值捕获**，改外层局部不会改变已生成闭包。  
6. **import** 区分 native 与 `.glk` 库；库无 main。  
7. 用算法小例子与「扫魔数」脚本衔接逆向主题。
