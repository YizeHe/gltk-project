## 5.0 为什么要异步？

逆向批处理常见需求：

- 同时分析很多文件；  
- 一边读盘一边算哈希；  
- 主线程将来接 GUI 消息循环，后台跑重活。

GrokLang 的 `async`：**每个 `spawn` 在独立 VM 克隆 + Go goroutine** 上跑（见 `docs/ASYNC.md`），适合并行扫样本，而不是共享可变全局的复杂多线程业务。

```text
async.spawn(fn, args)
        │
        ▼
  新 goroutine + VM 克隆（chunk/native 共享，globals 浅拷贝）
        │
        ▼
  future ── await / await_all / ready
```

## 5.1 错误处理再深化

### 5.1.1 throw / catch

```glk
try {
  throw "reason"
} catch e {
  out.println(e)
}
```

### 5.1.2 校验函数

```glk
fn parse_port(s) {
  let n = int(s)
  if n < 1 || n > 65535 {
    throw "port out of range: " + ("" + n)
  }
  return n
}
```

### 5.1.3 Result 风格（不抛到顶层）

```glk
fn result_ok(v) { return {ok: true, value: v, error: ""} }
fn result_err(msg) { return {ok: false, value: null, error: msg} }

fn safe_parse_port(s) {
  try {
    return result_ok(parse_port(s))
  } catch e {
    return result_err(e)
  }
}
```

调用方：

```glk
let r = safe_parse_port("0")
if r.ok {
  // use r.value
} else {
  // r.error
}
```

### 5.1.4 嵌套与 rethrow

内层 catch 后可以再 `throw` 给外层，附加上下文。

### 5.1.5 边界

- `throw` 与部分调用错误可捕获；  
- 不是所有 VM abort 都会进 catch；  
- 库边界推荐 **Result map** 或 **明确 throw 约定**。

## 5.2 `async.spawn` / `await` / `ready` / `sleep`

```glk
import async

fn slow_square(n) {
  async.sleep(30)
  return n * n
}

let f = async.spawn(slow_square, [3])  // args 用数组传入
out.println(async.ready(f))             // 可能 false
let r = async.await(f)                  // 9
```

| API | 作用 |
|-----|------|
| `spawn(fn, args_array?)` | 异步执行，返回 future |
| `await(future)` | 阻塞等待结果 |
| `await_all([f1,f2,...])` | 等一组，返回结果数组 |
| `ready(future)` | 是否完成 |
| `sleep(ms)` | 睡眠毫秒 |

**注意**：被 spawn 的函数应是**顶层 `fn`** 或可调用的函数值；`args` 是**一个数组**，对应参数列表。

```powershell
.\gltk.exe run learn\examples\ch05_02_async_spawn.glk
```

## 5.3 `async.parallel`：并行 map

```glk
fn work(item) {
  async.sleep(20)
  return {id: item, score: item * 10}
}

let results = async.parallel(work, [1, 2, 3, 4, 5])
// results[i] 对应 items[i] 的返回值
```

典型用途：对文件路径列表并行调用分析函数。

```powershell
.\gltk.exe run learn\examples\ch05_03_async_parallel.glk
```

## 5.4 Channel / Mutex / WaitGroup

### Channel

```glk
let ch = async.channel(4)   // 缓冲容量
async.send(ch, value)
let msg = async.recv(ch)    // {ok, value, closed}
async.close(ch)
```

可选超时：`send/recv` 第三参 `timeout_ms`（`-1` 阻塞，见文档）。

### Mutex

```glk
let mu = async.mutex()
async.lock(mu)
// critical section
async.unlock(mu)
```

### WaitGroup

```glk
let wg = async.waitgroup()
async.wg_add(wg, 2)
// 每个任务结束 async.wg_done(wg)
async.wg_wait(wg)
```

**spawn 的任务函数必须是顶层函数**（不要在 `main` 里 `fn task()`）。

```powershell
.\gltk.exe run learn\examples\ch05_04_channel_mutex.glk
```

## 5.7 常见错误

| 问题 | 处理 |
|------|------|
| spawn 后永远不 await | 泄漏/提前退出；记得 await 或 wg_wait |
| 在 main 内声明 fn 给 spawn | 解析失败；改顶层 fn |
| 假设共享可变全局 | 每任务 VM 克隆；用返回值/channel 汇合 |
| parallel 函数签名 | 单参数 `item` |
| try 包不住一切 | 关键路径自己 throw 或 Result |
